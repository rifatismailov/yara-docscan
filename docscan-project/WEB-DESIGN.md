# Веб-інтерфейс DocScan на ПК — план (2026-11-23)

Керування DocScan на самому ПК з браузера: **https://127.0.0.1:8741/** (порт 8741 — щоб не конфліктувати з
Anthophila_Hive на 8740; змінюється параметром інсталятора `-WebPort`).

**Стан (2026-11-23):** усі 4 етапи зроблено (код `watcher-go/web/`, `watcher-go/settings.go`, локальні списки у watcher,
updater `-CheckConfig` / перечитування конфігу / `check-now` / локальна політика, інсталятор, CI), перевірено на
тестовому ПК. Реліз — коли веб буде остаточно погоджено.

## 1. Що це і де працює

| | |
|---|---|
| Програма | `<InstallDir>\web\docscan-web.exe` (Go, лише стандартна бібліотека + `golang.org/x/sys`, як watcher) |
| Служба | **DocScanWeb**, SYSTEM, автозапуск; `-NoWeb` в інсталяторі — без неї |
| Адреса | лише `127.0.0.1:8741` (з мережі недоступна) |
| Дані | `C:\ProgramData\DocScan\web\` — сертифікат, ключ, хеш пароля; доступ лише SYSTEM і Адміністратори |

Watcher лишається сканером, updater — оновленнями; веб лише змінює їхні файли налаштувань і перезапускає служби.

## 2. HTTPS і вхід

**Сертифікат** генерує `docscan-web.exe -InitTLS` під час встановлення:
- ECDSA P-256, самопідписаний, **не CA** (`CA:FALSE` — не може підписати інші сертифікати), лише для `127.0.0.1`
  і `localhost`, `serverAuth`, 5 років;
- ключ — `web\key.pem` (ACL: SYSTEM, Адміністратори); публічна частина — у довірені кореневі сертифікати Windows
  (`Cert:\LocalMachine\Root`), щоб браузер не попереджав; деінсталяція її прибирає;
- переустановлення: сертифікат лишається, доки не закінчується (менше 90 днів — новий).

**Пароль** генерує `docscan-web.exe -InitAuth` під час встановлення (користувач `admin`):
- 20 випадкових символів; зберігається лише хеш (PBKDF2-SHA256, 600 000 ітерацій, сіль) у `web\auth.json`;
- сам пароль — у `web\initial-password.txt` (ACL: SYSTEM, Адміністратори) і у виводі інсталятора;
- **перший вхід вимагає змінити пароль** (≥ 12 символів), після цього `initial-password.txt` видаляється;
- забули — `docscan-web.exe -ResetPassword` від адміністратора (новий тимчасовий пароль і той самий файл).

**Захист** (як у Hive): сесія — cookie `Secure; HttpOnly; SameSite=Strict`, 30 хв без дій; CSRF-токен у кожній
формі; перевірка `Host` (лише `127.0.0.1:<порт>` / `localhost:<порт>` — від DNS rebinding); невдалі входи —
зростаюча затримка (1, 2, 4 … до 15 хв). На термінальному сервері до 127.0.0.1 може звернутися будь-який
користувач RDP — тому пароль, а не довіра до адреси.

## 3. Сторінки

| Сторінка | Що показує / робить |
|---|---|
| **Стан** | версія програми, правил (і звідки), списків (serial, ключ), служби watcher / updater / Wazuh-агент, режим, останні оновлення (`docscan-updates.json`), черга watcher |
| **Виявлення** | записи `docscan-results.json` (і ротованих): фільтри — рівень, дата, шлях, правило / список; запис повністю (findings, правила yara, `list`, `disarm`) |
| **Макроси / документ** | на записі виявлення — знахідки з поясненнями, докази (віддалений шаблон, DDE, VBA, ярлик, архів), правила YARA з описом і місцем; код VBA зі сховища macros\ з підсвіченими підозрілими рядками |
| **Карантин** | файли в карантині: звідки, коли, чому (запис списку / правило); **відновити**, **видалити** |
| **Оновлення** | усе з `updater.json`: режим, дзеркало програми, дзеркало правил, `extra_public_keys`, списки (адреса, ключі, токен), розклад, вікно; «перевірити зараз» (`-Once`) |
| **Режим watcher** | повний / DetectOnly, теки під наглядом, карантин загальних файлів, кількість сканувань, критичний пошук увімк./вимк. |
| **Чорний список** | **тимчасово вимкнути блокування**: 1 год / 4 год / до кінця дня / до ручного ввімкнення; видно, хто і до коли |
| **Списки** | списки з дзеркала (лише перегляд) + **локальні** білий / чорний (редагування з тією самою перевіркою, що `-CheckList`) |
| **Політика** | `docscan-policy.yar`: пакетна і **локальна** версії, редагування, перевірка компіляції, різниця з пакетною |
| **Сканування** | скан документів на вибраних локальних дисках (без системних і програмних тек), флешка / не системний диск повністю, провідник `/scan/browse` для тек і файлів, дія повідомити / лікувати / видалити (з підтвердженням); повного скану всіх файлів немає навмисно; хід зі смужкою і зупинкою, історія з переходом до знахідок; режим авто-скану знімних носіїв (`usb_scan`) |
| **Журнал** | `watcher.log`, `updater.log`, дії у веб (хто що змінив) |
| **Обліковий запис** | зміна пароля |

## 4. Як веб змінює DocScan (без зламу оновлень)

- **`updater.json`** — веб пише файл, перевіряє його новою командою `docscan-updater -CheckConfig <файл>` (той самий
  код, що читає служба), лише тоді замінює і перезапускає DocScanUpdater.
- **Режим watcher** — `C:\ProgramData\DocScan\settings.json` (новий): watcher читає його поверх параметрів служби.
  Режим і пауза чорного списку діють одразу (перечитування, як у списків); теки / кількість сканувань —
  перезапуском служби. `install.json` оновлюється теж, щоб переустановлення не повернуло старе.
- **Пауза чорного списку** — `settings.json` → `blacklist_paused_until` (час або `manual`). Під час паузи збіг з
  чорним списком дає HIGH з `disarm: paused` (повідомлення є, карантину немає). Після паузи — прохід по наявних
  файлах (sweep.go). Пауза й кінець паузи — записи у Wazuh.
- **Локальні списки** — `lists\whitelist.local.json` / `blacklist.local.json`: watcher застосовує їх **разом** зі
  списками з дзеркала (у записі для Wazuh — `list.source: local | mirror`); дзеркало їх не перезаписує.
- **Локальна політика** — `C:\ProgramData\DocScan\policy\docscan-policy.yar`: веб перевіряє компіляцію (копія правил
  з новою політикою, yara64), ставить її поверх `rules\docscan-policy.yar`, перезапускає watcher. Updater після
  кожного оновлення правил знову ставить локальну політику (якщо компілюється; інакше — пакетна + `error` у Wazuh).
- **Карантин** — біля кожного файлу `*.docscan-bak` watcher пише `*.docscan-bak.json`: звідки, sha256, час, причина
  (правило / запис списку), вид (`quarantined` — файл прибрано; `backup` — оригінал до знешкодження документа).
  **Відновити** — файл повертається на місце, а в локальний білий список додається запис `path` + `sha256` (інакше
  watcher одразу забрав би його знову). **Видалити** — файл і опис зникають. Обидві дії — у Wazuh.
- **Аудит** — кожна дія у веб — запис `event: "Admin"` у `docscan-results.json` (Wazuh-агент уже читає цей файл):
  хто, що, було → стало. Правило на менеджері Wazuh — окремо (з погодженням).

## 5. Етапи

1. ✅ **Основа:** `docscan-web.exe` + служба, `-InitTLS` / `-InitAuth` / `-ResetPassword`, вхід і зміна пароля,
   сторінки **Стан**, **Виявлення**, **Журнал**; аудит; інсталятор (сертифікат у Root, пароль, служба, `-NoWeb`,
   `-WebPort`), деінсталяція, збірка в cirun і пакеті.
2. ✅ **Налаштування:** **Оновлення** (`-CheckConfig` в updater), **Режим watcher** (`settings.json`), **пауза чорного
   списку**.
3. ✅ **Списки і політика:** локальні списки (watcher), локальна політика (веб + updater).
4. ✅ **Карантин:** перегляд (звідки і чому — із запису виявлення з тим самим sha256, опис біля файлів не потрібен), відновлення, видалення.
5. ✅ **Сканування** (2026-11-23): скан документів (повний скан прибрано того ж дня: на Mac зламав IDE), скан шляху / знімного диска, авто-скан флешок і USB-дисків — у watcher
   (`scanjob.go`, `drives/`), веб лише кладе запит у `scan\` і показує `scan\status.json` / `history.json`;
   те саме з командного рядка (`docscan-watcher -ScanDocs | -ScanPath`). Тести на Mac; Windows — ▷ і флешка на стенді.
