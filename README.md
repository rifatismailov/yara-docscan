> [!NOTE]
> This is a **fork of [VirusTotal/yara](https://github.com/VirusTotal/yara) 4.6.0** that adds a new
> module, **`docscan`**, for detecting and disarming weaponised documents. Everything else is
> upstream YARA, unchanged. See [About YARA](#about-yara) below.
>
> 📖 **Full documentation:** [English](docscan-project/SCAN-FLOW.en.md) · [Українська](docscan-project/SCAN-FLOW.md)

## What DocScan adds

`docscan` looks inside a document's **structure** (not its extension and not just raw bytes) and
reports the attack vector, the evidence and a verdict. One `yara64.exe` run per file does it all:

1. **Pass 1 — detection.** The module parses the document and exposes facts; the policy rules decide.
2. **Pass 2 — vendor rules over what was unpacked:** the decompressed VBA code and the embedded parts
   (`.rels`, OLE objects and package payloads, ActiveX, macro sheets, altChunk, RTF objects).
3. **Pass 3 — critical information** (every PC; `-NoCritical` turns it off): if the document **text** matches
   the critical rules (`critical/*.yar` of the rules package), the full text is split into fragments and queued as JSON for the E5Search
   service. YARA gives no verdict here.
4. **Disarm** the document in place (backup first), then one JSON line per file for a SIEM.

On Windows the hostile document is **never parsed with the watcher's SYSTEM rights**: the same `yara64.exe`
starts itself again as a sandboxed worker (restricted Users-level token, untrusted integrity, no privileges,
job object) that parses from memory and only reports back; the parent (the broker) parses nothing and does the
file writes — macro dump, queue line, backup and cure. The command line and the output stay the same.

| Vector | Verdict |
|---|---|
| Remote template injection (`attachedTemplate` → URL, T1221) | HIGH |
| Follina / protocol handlers (`ms-msdt:`, `search-ms:` …) | HIGH |
| `DDEAUTO` / DDE fields and Excel DDE formulas / `ddeLink` (T1559.002) | HIGH |
| Suspicious VBA macros (CFB + MS-OVBA decompression) / any macro | HIGH / MEDIUM |
| Embedded PE or LNK, OLE Package with an executable or script | HIGH |
| Equation Editor objects (CVE-2017-11882), ActiveX browser control | HIGH |
| RTF `\objupdate`, PDF auto-JavaScript with dangerous APIs, `/Launch` | HIGH |
| Malicious LNK (URL / obfuscated args, remote executable, LOLBin target) | HIGH / MEDIUM |
| External OLE / frame, ActiveX, altChunk (CVE-2023-36884), Excel 4.0 macro sheets | MEDIUM |

File types are recognised by magic bytes: OOXML (docx/xlsx/pptx…), OLE (doc/xls/ppt), RTF, PDF, LNK.

### Detection policy lives in YARA rules

The module only parses documents and exposes **facts** (`docscan.vba_code`, `docscan.external_rels[]`,
`docscan.dde[]`, `docscan.embedded[]`, `docscan.packages[]`, `docscan.activex[]`, `docscan.parts[]`, …).
What counts as HIGH or MEDIUM, how a finding is named, its human-readable text and what gets disarmed is
decided by ordinary rules in [`docscan-policy.yar`](https://github.com/rifatismailov/yara-docscan-rules/blob/main/docscan-policy.yar) (rules repository):

```yara
rule DS_REMOTE_TEMPLATE
{
  meta:
    severity = "HIGH"                 // HIGH / MEDIUM / INFO
    finding  = "REMOTE_TEMPLATE"      // name in the JSON
    disarm   = "remote_template"      // what --docscan-disarm removes (optional)
  condition:
    for any rel in docscan.external_rels : (
      rel.type iendswith "/attachedTemplate" and
      rel.target matches /^((https?|s?ftps?):\/\/|\\\\|file:\/\/([^\/]|\/\/))/i )
}
```

Edit the policy to fit your organisation — no rebuild needed. Vendor rules (8,068 rules from
signature-base, Elastic, Yara-Rules, bartblaze, InQuest, ditekSHen, ReversingLabs and YARA-Forge core at pinned
versions, filtered rule by rule) are generated by `tools/build_vendor_rules.py` of [yara-docscan-rules](https://github.com/rifatismailov/yara-docscan-rules); we do not
write our own signatures.

### New command-line flags

| Flag | What it does |
|---|---|
| `--docscan-json` | One JSON line per file: `findings`, `findings_text`, `verdict` (from the policy), `evidence` (URLs defanged), vendor matches on the file / document / VBA / parts, `details` |
| `--docscan-disarm` | Cures the file in place as the matching policy rules say (`meta.disarm`): strips the macro / external relationship / DDE / embeddings, breaks `\objupdate`, deletes a malicious LNK, quarantines what cannot be cured |
| `--docscan-backup-dir=DIR` | Backups and quarantined files go to `DIR` (otherwise `<file>.docscan-bak`) |
| `--docscan-extract=FILE` | Writes the decompressed VBA to `FILE` (the watcher keeps it as the macro store) |
| `--file-vars` | THOR/LOKI external variables (`filename`, `filepath`, `extension`, `filetype`, `owner`) per file; implied by `--docscan-json` |
| `--critical-rules=FILE\|DIR` `--critical-out=FILE` `[--critical-chunk=700,120]` | Pass 3: match the rules (one `.yar`, or every `*.yar` of a folder compiled together, each file in its own namespace) against the document text; on a match append one JSON line (fragments + metadata) to the queue file |
| `--docscan-confine-check` | Windows: test the sandbox (the worker must not be able to write, read private files or start a process); `RESULT: CONFINED` |
| `--docscan-no-sandbox` | Windows, diagnostics: parse in-process (job object and removed privileges only) |

```console
$ yara64 -w --docscan-json --docscan-disarm docscan-project/rules/docscan-index.yar invoice.docm
{"ftype":"ooxml","findings":["MACRO_PRESENT","MACRO_SUSPICIOUS","MACRO_AUTOEXEC"],"verdict":"HIGH",
 "evidence":{"vba_evidence":"powershell | Shell | DownloadFile | AutoOpen"},
 "yara_matches":["VBA_AutoExec_DownloadCradle"],"yara_part_matches":[],"details":[…]}
docscan-disarm: invoice.docm -> removed:vbaProject.bin
```

### File watcher and deployment

The file watcher `docscan-watcher.exe` (`docscan-project/watcher-go/`, Go, a Windows service running as SYSTEM;
the older PowerShell watcher `docscan-project/watcher/docscan-watcher.ps1` stays in the package as a fallback,
`install.ps1 -WatcherEngine ps`) watches folders, scans every new or changed file with one `yara64` run, disarms documents, keeps the VBA code of documents
with macros (`C:\ProgramData\DocScan\macros\`, optionally copied to a collector), retries the cure of files
held open by Word, and appends one JSON line per file (with a human-readable `summary`) to
`C:\ProgramData\DocScan\results\docscan-results.json` for the Wazuh agent. With pass 3 on, matching
documents go to `C:\ProgramData\DocScan\critical\critical.json`; another program sends them to E5Search.

Install or update on a workstation (PowerShell as administrator) from the
[GitHub release](https://github.com/rifatismailov/yara-docscan/releases/latest) (yara64, watcher, updater,
scripts). The rules are released separately in
[yara-docscan-rules](https://github.com/rifatismailov/yara-docscan-rules/releases/latest): download the rules
bundle **before** installing and pass it with `-Rules` (file, UNC path or URL):

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor [Net.SecurityProtocolType]::Tls12   # GitHub needs TLS 1.2 (Windows PowerShell 5.1)
$f = "$env:TEMP\DocScan-Install.ps1"
irm https://github.com/rifatismailov/yara-docscan/releases/latest/download/DocScan-Install.ps1 -OutFile $f
$r = "$env:TEMP\DocScan-rules-bundle.zip"
irm https://github.com/rifatismailov/yara-docscan-rules/releases/latest/download/DocScan-rules-bundle.zip -OutFile $r
powershell -ExecutionPolicy Bypass -File $f -Rules $r                       # normal PC
powershell -ExecutionPolicy Bypass -File $f -Rules $r -DetectOnly           # pilot: detection and alerts only
powershell -ExecutionPolicy Bypass -File $f -Rules $r -Whitelist <file> -Blacklist <file>   # + the organisation's lists
```

Critical-information rules (pass 3) are written by each organisation for itself: how to decide what is critical and
how to write the rules - [CRITICAL-RULES.md](docscan-project/CRITICAL-RULES.md) (Ukrainian). They travel in the same rules
package as the detection rules: `critical/*.yar` of `DocScan-rules.zip` (any number of files), built and tested by one
tool - `cirun rules-release --dir <rules> --critical <critical rules repository>` - and installed on every PC by
DocScanUpdater (`-NoCritical` turns pass 3 off on a PC).

The installer verifies the package and the signed rules, adds Defender exclusions, configures the Wazuh agent and
registers the Windows services "DocScan Watcher" (`DocScanWatcher`: watches files, runs yara64) and `DocScanUpdater`
(program, rules and lists updates; mode `github` | `mirror` | `marker` | `off`, set with `-UpdateMode`, or the
organisation's whole `updater.json` at once with `-UpdateConfig <file | URL>`; design: [UPDATE-DESIGN.md](docscan-project/UPDATE-DESIGN.md), Ukrainian).

The organisation's **white list** (`whitelist.json`: files not scanned) and **black list** (`blacklist.json`: HIGH and
quarantine before any scan) name files by path mask, by the network folder a shortcut points to, or by sha256; the
organisation keeps them itself, by hand or on its own mirror (signed with its key, checked daily by DocScanUpdater).
Format and diagrams: `docscan-project/deploy/README.txt`, [LISTS-FLOW.md](docscan-project/LISTS-FLOW.md). Wazuh manager rules: `docscan-project/deploy/manager/local_rules.docscan.xml`.

A **local web interface** for the PC's administrator - `docscan-web.exe`, the service `DocScanWeb`, only on
`https://127.0.0.1:8741/` (HTTPS with a certificate made at install, login `admin`, every action audited to Wazuh) - shows
the state and detections and sets the mode, the black-list pause, updates, local exceptions, the quarantine, the local
policy and the stored macros ([WEB-DESIGN.md](docscan-project/WEB-DESIGN.md), Ukrainian). Its page **Сканування** checks
files already on the disk (the watcher only sees new and changed ones):

- **documents** on the chosen local disks, without system and program folders;
- a **removable medium** (USB stick, USB disk, SD) or a non-system disk, all files. A new removable medium is scanned on its own
  (`usb_scan`: as the mode / full / report only / off);
- folders and files picked in a **browser** of the PC's disks.

The action is report only, cure (disarm, quarantine) or delete the threats with no copy (after a confirmation). Files in
program folders (`Windows`, `Program Files`, `AppData\Local\Programs`) are only ever reported. There is deliberately no
"scan every file on every disk": disarming or quarantining files of installed programs breaks those programs. The same
from PowerShell: `docscan-watcher.exe -ScanDocs | -ScanPath E:\ [-ScanDetect | -ScanDelete] [-Wait]`, `-ScanStatus`,
`-ScanCancel all`.

## About YARA

YARA is a pattern-matching tool for identifying and classifying malware: rules describe
families by textual or binary patterns plus a boolean condition. See the
[upstream repository](https://github.com/VirusTotal/yara) and the
[documentation](https://yara.readthedocs.io/) for the rule language and API.

> [!IMPORTANT]
> Upstream YARA is in maintenance mode; new development happens in
> [YARA-X](https://virustotal.github.io/yara-x/). This fork is based on YARA 4.6.0.
