> [!NOTE]
> This is a **fork of [VirusTotal/yara](https://github.com/VirusTotal/yara) 4.6.0** that adds a new
> module, **`docscan`**, for detecting and disarming weaponised documents. Everything else is
> upstream YARA, unchanged. See [About YARA](#about-yara) below.
>
> 📖 **Full documentation:** [English](docscan-project/SCAN-FLOW.en.md) · [Українська](docscan-project/SCAN-FLOW.md)

## What DocScan adds

`docscan` looks inside a document's **structure** (not its extension and not just raw bytes) and
reports the attack vector, the evidence and a verdict. One `yara64.exe` run per file does it all:

1. **Pass 1 — detection.** The module parses the document and exposes facts; the policy rules decide.
2. **Pass 2 — vendor rules over what was unpacked:** the decompressed VBA code and the embedded parts
   (`.rels`, OLE objects and package payloads, ActiveX, macro sheets, altChunk, RTF objects).
3. **Pass 3 — critical information** (optional, selected PCs): if the document **text** contains phrases
   from the E5Search rules, the full text is split into fragments and queued as JSON for the E5Search
   service. YARA gives no verdict here.
4. **Disarm** the document in place (backup first), then one JSON line per file for a SIEM.

| Vector | Verdict |
|---|---|
| Remote template injection (`attachedTemplate` → URL, T1221) | HIGH |
| Follina / protocol handlers (`ms-msdt:`, `search-ms:` …) | HIGH |
| `DDEAUTO` / DDE fields and Excel DDE formulas / `ddeLink` (T1559.002) | HIGH |
| Suspicious VBA macros (CFB + MS-OVBA decompression) / any macro | HIGH / MEDIUM |
| Embedded PE or LNK, OLE Package with an executable or script | HIGH |
| Equation Editor objects (CVE-2017-11882), ActiveX browser control | HIGH |
| RTF `\objupdate`, PDF auto-JavaScript with dangerous APIs, `/Launch` | HIGH |
| Malicious LNK (URL / obfuscated args, remote executable, LOLBin target) | HIGH / MEDIUM |
| External OLE / frame, ActiveX, altChunk (CVE-2023-36884), Excel 4.0 macro sheets | MEDIUM |

File types are recognised by magic bytes: OOXML (docx/xlsx/pptx…), OLE (doc/xls/ppt), RTF, PDF, LNK.

### Detection policy lives in YARA rules

The module only parses documents and exposes **facts** (`docscan.vba_code`, `docscan.external_rels[]`,
`docscan.dde[]`, `docscan.embedded[]`, `docscan.packages[]`, `docscan.activex[]`, `docscan.parts[]`, …).
What counts as HIGH or MEDIUM, how a finding is named, its human-readable text and what gets disarmed is
decided by ordinary rules in [`docscan-project/rules/docscan-policy.yar`](docscan-project/rules/docscan-policy.yar):

```yara
rule DS_REMOTE_TEMPLATE
{
  meta:
    severity = "HIGH"                 // HIGH / MEDIUM / INFO
    finding  = "REMOTE_TEMPLATE"      // name in the JSON
    disarm   = "remote_template"      // what --docscan-disarm removes (optional)
  condition:
    for any rel in docscan.external_rels : (
      rel.type iendswith "/attachedTemplate" and
      rel.target matches /^((https?|s?ftps?):\/\/|\\\\|file:\/\/([^\/]|\/\/))/i )
}
```

Edit the policy to fit your organisation — no rebuild needed. Vendor rules (5,594 rules from
signature-base, Elastic, Yara-Rules, bartblaze, InQuest and ditekSHen at pinned commits) are generated by
`docscan-project/rules/tools/build_vendor_rules.py`; we do not write our own signatures.

### New command-line flags

| Flag | What it does |
|---|---|
| `--docscan-json` | One JSON line per file: `findings`, `findings_text`, `verdict` (from the policy), `evidence` (URLs defanged), vendor matches on the file / document / VBA / parts, `details` |
| `--docscan-disarm` | Cures the file in place as the matching policy rules say (`meta.disarm`): strips the macro / external relationship / DDE / embeddings, breaks `\objupdate`, deletes a malicious LNK, quarantines what cannot be cured |
| `--docscan-backup-dir=DIR` | Backups and quarantined files go to `DIR` (otherwise `<file>.docscan-bak`) |
| `--docscan-extract=FILE` | Writes the decompressed VBA to `FILE` (the watcher keeps it as the macro store) |
| `--file-vars` | THOR/LOKI external variables (`filename`, `filepath`, `extension`, `filetype`, `owner`) per file; implied by `--docscan-json` |
| `--critical-rules=FILE` `--critical-out=FILE` `[--critical-chunk=700,120]` | Pass 3: match `FILE` rules against the document text; on a match append one JSON line (fragments + metadata) to the queue file |

```console
$ yara64 -w --docscan-json --docscan-disarm docscan-project/rules/docscan-index.yar invoice.docm
{"ftype":"ooxml","findings":["MACRO_PRESENT","MACRO_SUSPICIOUS","MACRO_AUTOEXEC"],"verdict":"HIGH",
 "evidence":{"vba_evidence":"powershell | Shell | DownloadFile | AutoOpen"},
 "yara_matches":["VBA_AutoExec_DownloadCradle"],"yara_part_matches":[],"details":[…]}
docscan-disarm: invoice.docm -> removed:vbaProject.bin
```

### File watcher and deployment

`docscan-project/watcher/docscan-watcher.ps1` (Windows, PowerShell 5.1, runs as SYSTEM) watches folders,
scans every new or changed file with one `yara64` run, disarms documents, keeps the VBA code of documents
with macros (`C:\ProgramData\DocScan\macros\`, optionally copied to a collector), retries the cure of files
held open by Word, and appends one JSON line per file (with a human-readable `summary`) to
`C:\ProgramData\DocScan\results\docscan-results.json` for the Wazuh agent. With pass 3 on, matching
documents go to `C:\ProgramData\DocScan\critical\critical.json`; another program sends them to E5Search.

Install on a workstation (PowerShell as administrator), from an HTTP server holding the package:

```powershell
irm http://<server>:8080/docscan/DocScan-Setup.ps1 | iex            # normal PC
irm http://<server>:8080/docscan/DocScan-Setup-Pilot.ps1 | iex      # pilot: detection and alerts only
irm http://<server>:8080/docscan/DocScan-Setup-Critical.ps1 | iex   # + pass 3 (critical information)
```

The installer verifies the package, adds Defender exclusions, configures the Wazuh agent and registers the
"DocScan Watcher" task. Wazuh manager rules: `docscan-project/deploy/manager/local_rules.docscan.xml`.

### Building

Same as upstream YARA — the module is compiled in by default.

```sh
# macOS / Linux
./bootstrap.sh && ./configure && make
```
```powershell
# Windows (VS Build Tools 2022)
nuget restore windows\vs2019\yara.sln
msbuild windows\vs2019\yara.sln /t:yara;yarac /p:Configuration=Release /p:Platform=x64 /p:PlatformToolset=v143
```

## About YARA

YARA is a pattern-matching tool for identifying and classifying malware: rules describe
families by textual or binary patterns plus a boolean condition. See the
[upstream repository](https://github.com/VirusTotal/yara) and the
[documentation](https://yara.readthedocs.io/) for the rule language and API.

> [!IMPORTANT]
> Upstream YARA is in maintenance mode; new development happens in
> [YARA-X](https://virustotal.github.io/yara-x/). This fork is based on YARA 4.6.0.
